# Руководство по участию в разработке (Contributing Guide)

Спасибо за интерес к проекту **Telegram Music Bot**! Мы ценим вклад сообщества в улучшение функционала и стабильности бота.

---

## Как внести вклад

1. **Создайте Issue**: перед началом масштабной работы рекомендуется создать Issue для обсуждения предлагаемой функциональности или найденного бага.
2. **Форкните проект**: создайте собственный форк репозитория на GitHub.
3. **Создайте ветку**: используйте понятные префиксы для названий веток:
   - `feat/название-фичи`
   - `fix/описание-бага`
   - `docs/улучшение-документации`
4. **Разрабатывайте аккуратно**:
   - Придерживайтесь стиля кодовой базы (PEP 8, асинхронный код на `asyncio` / `aiogram 3`).
   - Сохраняйте архитектурные инварианты (семафоры, валидация аутентичности кандидатов, обработка исключений).
   - Не добавляйте секретные ключи, токены и реальные конфигурации в файлы репозитория.

---

## Тестирование

Перед отправкой изменений обязательно убедитесь, что весь тестовый набор выполняется без ошибок:

```bash
# Запуск тестов
python -m pytest

# Проверка синтаксиса и форматирования git diff
git diff --check
```

Все новые функции и исправления ошибок должны сопровождаться соответствующими тестами в директории `tests/`.

---

## Оформление Pull Request

1. Убедитесь, что ваша ветка актуализирована с веткой `main` основного репозитория.
2. Сформируйте понятные коммиты в соответствии с conventional commits:
   - `feat: ...`
   - `fix: ...`
   - `docs: ...`
   - `test: ...`
   - `refactor: ...`
3. Откройте Pull Request с кратким описанием сути изменений и ссылкой на соответствующий Issue (если есть).
